## 3. 当前算法判断

当前不是缺计划，而是 LTR 修复线已经推进到 mixed safety 阶段，但候选模型还没有过保护门禁。

已确认事实：

- `ltr_v2_full_20260422` 把命中率从 `25.3%` 拉到 `33.8%`。
- 召回命中率仍是 `72.5%`，说明 `R1_召回未命中` 还没有被修。
- 纯 residual R2 训练的 `round2` 回退到 `30.2%`，说明只喂 hard case 会学偏。
- 多个 mixed safety 模型已有产物，但 `do_not_break` 仍失败。

当前优先级：

1. 先把 mixed safety 的 `do_not_break` 违例看清并修到过门禁。
2. 再跑 full benchmark 判断是否能替换主基线。
3. 之后再进入 R1 召回修复。
4. 最后才做 Picker/CGR 的局部修复。

## 4. 第一阶段：LTR Mixed Safety 闭环

### 步骤 4.1 补 do-not-break 违例明细导出

目标：

让 `tools/train_ltr_v2.py` 在训练摘要中输出每个保护集失败 query 的明细，而不是只输出分组命中率。

建议输出字段：

- `query_id`
- `protect_group`
- `failure_target`
- `training_role`
- `correct_quota_id`
- `baseline_top1_id`
- `model_top1_id`
- `model_top1_score`
- `baseline_hit`
- `model_hit`
- `candidate_count`

改动范围：

- `tools/train_ltr_v2.py`
- `tests/test_train_ltr_v2.py`

验收命令：

```powershell
python -m pytest tests/test_train_ltr_v2.py -q
```

通过标准：

- 测试全绿。
- `evaluate_do_not_break()` 返回结构中包含违例明细。
- watch-only 组可以输出明细，但不能触发 `regression_guard_failed`。

### 步骤 4.2 复算现有 mixed safety 模型，拿到违例样本

目标：

用现有 mixed safety 数据复算，确认具体是哪些保护样本被打坏。

验收命令：

```powershell
python tools/train_ltr_v2.py `
  --input data/ltr_mixed_safety_training_data.csv `
  --output-dir output/ltr/model_v2_mixed_safety_diagnose `
  --do-not-break-eval reports/attribution/do_not_break_eval.json
```

通过标准：

- `output/ltr/model_v2_mixed_safety_diagnose/train_summary.json` 包含违例明细。
- 能明确最大失败组，例如 `lighting_guard`、`switch_guard` 或其他组。
- 不进入下一步前，必须在对话中列出最大失败组和前 5 个违例样本。

### 步骤 4.3 只修最大保护组

目标：

只处理一个最大失败保护组，不碰召回、Picker、CGR。

允许的修复方向：

- 调整 mixed safety 数据集的该保护组样本权重。
- 增加该保护组的 targeted seed。
- 修正明显错误或过宽的保护组标签。
- 若违例来自评估逻辑错误，先修评估逻辑。

禁止：

- 顺手改 `query_builder.py`。
- 顺手改 `pickers.py`。
- 顺手改 CGR 或 final validator。
- 为一个保护组引入全局排序规则。

验收命令：

```powershell
python -m pytest tests/test_train_ltr_v2.py tests/test_build_mixed_safety_ltr_dataset.py -q
```

通过标准：

- 最大保护组 delta 不再低于 `-0.02`。
- 其他 train_and_eval 保护组不新增失败。
- watch-only 组只观察，不阻塞。

### 步骤 4.4 训练 mixed safety 候选模型

验收命令：

```powershell
python tools/train_ltr_v2.py `
  --input data/ltr_mixed_safety_training_data.csv `
  --output-dir output/ltr/model_v2_mixed_safety_candidate `
  --do-not-break-eval reports/attribution/do_not_break_eval.json
```

通过标准：

- `do_not_break.regression_guard_failed = false`
- holdout 不明显退化。
- `train_summary.json` 记录 sample source、权重、保护组结果和违例明细。

### 步骤 4.5 跑 full benchmark 验收

验收命令：

## 5. 第二阶段：R1 召回修复

进入条件：

- 第一阶段 mixed safety 候选模型通过 do-not-break。
- full benchmark 不低于主基线。

目标：

降低 `R1_召回未命中`，提高召回命中率，当前基线召回命中率是 `72.5%`。

优先顺序：

1. query rewrite / route 修正。
2. candidate pool 合并策略。
3. 全专业同义词和导入侧同义词挖掘。
4. fast miss 升级到 standard retrieve。

每轮只选一个模块。

验收：

```powershell
python tools/run_benchmark.py --profile full --json-only
```

通过标准：

- 召回命中率高于 `72.5%`。
- 总命中率不下降。
- `R2/R3/R4` 不出现明显上涨。

## 6. 第三阶段：Picker / CGR 局部修复

进入条件：

- benchmark 归因显示 `R3` 或 `R4` 成为主要剩余问题。

执行原则：

- 每次只修一个归因聚类。
- 必须有对应 regression test。
- 修 Picker 时不碰 LTR。
- 修 CGR 时不碰 Picker。

验收：

- 对应 R 类下降。
- 总命中率不下降。
- `R1/R2` 不明显上涨。

## 7. 额外改进点，但不插队

这些是有价值的改进，但不能插到第一阶段前面。

### 7.1 训练摘要需要保存违例样本 CSV

除写入 `train_summary.json` 外，建议额外输出：

- `do_not_break_violations.csv`

这样方便人工检查和后续 OpenClaw 离线 review。

### 7.2 full benchmark 结果体积过大

当前 `output/benchmark_compare/*latest_result*.json` 超过 1GB。建议后续增加 compact result：

- 只保留 `bill_id / bill_name / stored_ids / algo_id / R类 / stage top1 / recall_rank`
- 完整大文件仍可选输出

这个改进只影响工具产物，不应影响算法。

### 7.3 progress 文档要同步

`reports/agent_state/progress.json` 曾经落后于真实测试状态。后续每轮修复结束应更新“当前真实下一步”，避免接续时读到旧问题。

### 7.4 OpenClaw 只进入离线优化

OpenClaw 可用于：

- 审查 do-not-break 违例样本。
- 聚类失败原因。
- 生成小范围 patch 建议。

但不能让 OpenClaw 在线替代 Jarvis 主匹配。
