主流程：Web 匹配任务

1. 上传React 创建任务，提交 Excel 到 /api/tasks。
2. 入库后端保存上传文件，创建 Task，投递 Celery。
3. 执行execute_match 选择本地或远程匹配后端。
4. 匹配main.run 读取、清洗、路由、召回、排序、校验。
5. 保存压缩 quotas、alternatives、trace 后写入 MatchResult。
6. 闭环前端展示、人工确认、OpenClaw 二审、经验和知识回流。

API 与页面地图

后端主路由

  • /api/auth：注册、登录、刷新、退出、当前用户。
  • /api/tasks：创建、列表、详情、取消、预览、进度。
  • /api/tasks/{id}/results：结果查看、确认、导出。
  • /api/admin/*：用户、配置、经验、知识、日志、分析、额度。
  • /api/tools/*：智能填价、编清单、主材查价。
  • /api/file-intake/*：统一上传、分类、解析、路由、确认。
  • /api/openclaw/*：外部审核兼容面和二审闭环。

前端主页面

  • /login：登录和注册。
  • /dashboard：系统概览。
  • /tasks/create：上传清单创建任务。
  • /tasks：任务列表。
  • /tasks/:taskId/results：结果、候选、确认、导出。
  • /tools/price-backfill、/tools/bill-compiler、/tools/material-price：工具入口。
  • /admin 和 /admin/*：管理端。

需要小心的地方

dict 字段是隐式合同。

核心匹配链路大量通过候选 dict 和 result dict 传递字段。改字段前先查生产者、消费者、trace 压缩和前端展示。

OpenClaw 是外部兼容面。

review-draft、review-confirm、task/result/export 相关字段要保持向后兼容。

运行时缓存可能跨任务复用。

src/runtime_cache.py 缓存省份级重对象。请求级状态要显式清理，避免污染下一次匹配。

本地和远程匹配路径都要想一遍。

MATCH_BACKEND=local 走 Celery 进程内匹配，remote 走 local_match_server.py。任务语义改动需要检查两条路径。
