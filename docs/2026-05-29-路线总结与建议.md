# 路线总结与建议

> 2026-05-29 | 基于全部实验结果的最终路线

---

## 已验证的事实

| 做了什么 | 结果 | 结论 |
|---|---|---|
| 修不对称偏差、置信度标定、gate、排序 | 无退化 | 算法更稳健，但不直接提准确率 |
| 导入福建 OSS 4.6万条 → 经验库 | **+36% top1** | 直接有效 |
| 微调 BGE 向量模型 | **-2%** | 单省数据训不出跨省泛化 |
| cluster 扩展 BM25 | 太慢 | 1.8GB national_index 工程不可行 |
| 加大 cluster bonus | 无变化 | cluster 匹配本身覆盖率不够 |

## 根本矛盾

**系统需要跨省知识，但训练数据只有一个省。**

福建 OSS → 福建语义 → 和安徽不通用  
微调 BGE → 福建嵌入 → 测安徽退化  
cluster → 理论可行 → 数据太大跑不动

## 正确的路线

### 路线：多省数据 + 经验库优先

**核心逻辑：经验库的"文本匹配"是跨省通用的。多省数据导入后覆盖面更广。**

```
步骤1: 导入浙江 OSS (13万对) → 经验库从 4.6万 → ~18万
步骤2: 导入江苏 OSS (4千对)  → 经验库 ~18万
步骤3: 跑基线测评

预期: top1 60% → 65-70%
```

**为什么这比模型训练靠谱：**
- 经验库用 FTS5 文本索引，搜"离心式泵"就找到"离心式泵"，不管福建还是安徽
- 不涉及任何模型、训练、省份差异
- 已验证有效（+36%）

### 远期：跨省概念索引（当数据充足时）

等有 3+ 省 OSS 数据后，从 national_index 的 cluster 中预计算一个轻量概念索引：

```
离线构建 (一次性):
  cluster_key → [浙江写法, 福建写法, 广东写法, ...] 的概念词集合
  → 输出 concept_index.jsonl (~5MB)

在线查询 (<5ms):
  搜"离心式泵" → 查到 concept_index 中匹配的概念词
  → 用概念词扩充 BM25 查询
```

**这比直接查 1.8GB national_index 快 1000 倍。**

## 不做的事

- ❌ 不再微调模型（单省数据不够）
- ❌ 不再逐 case 修（R2-2a~2e 已验证不可持续）
- ❌ 不再改 cluster（1.8GB 太大，除非预计算）
- ❌ 不再纠结 goldenset 100 条（样本太小，±2 就是 ±2%）
