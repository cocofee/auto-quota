# 通用修复方案：搜索词扩充 + 排序权重重平衡

> 2026-05-29 | 两个通用修改，不改任何具体 case

---

## 问题诊断

40 个失败分两类，各有一个通用修法：

| 类型 | 数量 | 根因 | 修法 |
|---|---|---|---|
| 召回失败 | 22 | BM25 搜不到（清单用词 ≠ 定额用词） | 搜索词扩充 |
| 排序失败 | 18 | param 权重太低，通用 reranker 主导 | 权重重平衡 |

---

## 修复 1：搜索词扩充

### 原理

经验库 10 万条 (bill, quota_name) 配对。每条都是一个"白话→术语"的翻译。
搜之前先查经验库，把术语词加到搜索词里。

```
"低压碳钢管" → 经验库 → "低压碳钢管 氩电联焊 DN50 碳钢管件"
              → 提取关键词: "氩电联焊" "DN50" "碳钢管件"
              → 扩充搜索: "低压碳钢管 氩电联焊 DN50 碳钢管件"
              → BM25 命中率提升
```

对所有清单通用：不管什么品类，经验库有对应记录就能扩充。

### 改动

`src/goal_search/searcher.py` — `GoalSearcher.search()` 方法中，BM25 查询前加一步。
或者在 `src/hybrid_searcher.py` — `collect_prior_candidates()` 中扩充查询词。

```
改动量: ~15 行
```

---

## 修复 2：排序权重重平衡

### 原理

当前 `compute_candidate_structured_score` 中：
- rerank_score 权重 40%（通用 CrossEncoder，建筑领域区分力不足）
- param_score 权重 10%（参数精确匹配，区分力强但被压制）

改为：
- rerank_score 权重 30%
- param_score 权重 20%（原 10%）

差值从 30% 缩小到 10%。param 信号（含名称语义检查）不再被 rerank 压过。

### 改动

`src/candidate_scoring.py` — `compute_candidate_structured_score()` 
修改 `w_rerank` 和 `w_param` 两行。

```
改动量: ~5 行
```
