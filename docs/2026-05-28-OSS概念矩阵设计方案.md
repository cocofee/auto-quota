# OSS 概念矩阵设计方案

## 核心思路

从 15,285 条 OSS 人工匹配记录中构建一个 **清单概念 × 定额概念** 矩阵。
查询时：输入一个清单，矩阵返回"最可能匹配的定额概念"，用这个概念去引导排序。

## 矩阵结构

```
              定额概念列（术语）
              ┌──────┬──────┬──────┬──────┐
        离心式泵│  12  │   0  │   3  │  0   │  ← 支持度
清单    电力电缆│   0  │  89  │   0  │  15  │
概念    套管   │   0  │   0  │  67  │   0  │
行      配电箱 │   2  │   0  │   0  │  45  │
              └──────┴──────┴──────┴──────┘
              泵安装  电缆敷设 钢套管  成套配电
```

每个格子 = OSS 中"这个清单概念 → 这个定额概念"被人工匹配了多少次。

## 构建方式

1. 从经验库提取 15,285 条 (bill_name, quota_name) 记录
2. 用 jieba 对清单名和定额名做中文分词（项目已有工程词典）
3. 清单侧概念 = 清单名去通用词后的关键词集合
4. 定额侧概念 = 定额名去通用词后的关键词集合  
5. 矩阵 cell[清单词][定额词] += 1（每条记录贡献一次）
6. CF-IDF 归一化：频繁共现降权，罕见共现加权

## 查询方式

```
输入清单: "离心式泵" → jieba分词 → [离心式, 泵]
                              ↓
矩阵查询: [离心式, 泵] × 定额概念列
                              ↓
返回: [(泵安装, 0.89), (设备减震, 0.72), (台座重量, 0.68), ...]
                              ↓
对安徽候选定额, 每个候选算概念重叠分:
  candidate_concept_score = Σ(矩阵权重 × I(candidate包含该概念))
                              ↓
加入排序偏置: rank_score += candidate_concept_score * 0.05
```

## 速度

- 离线构建：~5秒（1256×2000 稀疏矩阵）
- 在线查询：~0.5ms/条（jieba分词 + 稀疏矩阵点乘）
- 对 2 分钟预算几乎无影响

## 与现有 OSS 召回矩阵的区别

| | 现有 OSS 矩阵 | 概念矩阵 |
|---|---|---|
| 维度 | 省份 × 族 × 清单名 × 定额号 | 清单概念 × 定额概念 |
| 省份依赖 | 硬过滤（安徽无数据=不可用） | 无省份依赖 |
| 覆盖 | 2族/904条 | 全族/~2000概念 |
| 用途 | 检索时注入候选 | 排序时偏置加分 |
| 信号冲突检查 | 有（DN/截面等） | 需额外加 |

## 实现步骤

1. 构建概念矩阵（离线，~100行Python）
2. 新增 `src/oss_concept_scorer.py`（~80行）
3. 在 `candidate_scoring.py` 中调用（~5行）
4. 跑基线测评验证

## 预期效果

- 排序失败案例减少（正解排第2/3的被概念匹配推上来）
- top1 +3~5%（概念偏置修正排序错误）
- 跨省通用（安徽、广东、福建同一套概念）
