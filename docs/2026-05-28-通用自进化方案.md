# 通用自进化匹配方案

> 2026-05-28 | 不是修一个 case，是建一套能自己变好的系统

---

## 1. 问题本质

现在的流程：

```
发现一个错 → 分析原因 → 改代码/调参数 → 跑测评 → 又发现一个错 → ...
```

这是打地鼠。用户要的是：**不管什么省份、什么清单，系统能自己从 OSS 数据里学到规律，持续变好。**

## 3. 为什么这个方案是"通用"的

### 3.1 不依赖具体清单

不是"离心式泵配错了→修离心式泵的规则"，而是：

```
微调后的向量模型学到了:
  "XX式泵" ≈ "泵类设备安装" 的语义关系
  "DNXXX" ≈ "公称直径XXXmm以内" 的参数映射
  "YJV-*" ≈ "铜芯电力电缆敷设" 的型号对应
```

这些规律对 **所有清单** 生效，不管见没见过。

### 3.2 不依赖具体省份

训练数据来自福建 OSS，但模型学的是 **语义层面** 的规律：

```
福建: "离心式泵" → "泵类设备安装 单级离心水泵  0.2t"
安徽: "离心式泵" → "泵类设备安装 单级离心水泵  0.2t" (同一概念)
```

向量模型微调后，两个省份的同一概念在向量空间中距离更近。

### 3.3 可持续积累

```
今天: 福建761个XML → 训出 v1 模型 → 准确率 +5%
明天: 浙江449个XML → 训出 v2 模型 → 准确率 +3%
下周: 新省份数据  → 训出 v3 模型 → 准确率 +2%
```

不需要改任何代码，只需加数据、重训、部署。

## 4. 技术细节

### 4.1 步骤1: 生成训练三元组

**输入**: OSS 经验库 (bill_name, quota_name) 配对

**流程**:
```python
for each OSS record:
    # 正样本: OSS 中人工匹配的定额
    positive = (bill_text, oss_quota_name)

    # 负样本: 用现有流水线搜出来的错误候选
    candidates = search_pipeline(bill_text)  # top 25
    negatives = [c for c in candidates if c not in oss_quota_names]

    # 硬负样本: 和正解很像但不对的 (最难区分的)
    hard_negatives = top_k_by_similarity(negatives, positive, k=3)

    # 输出三元组
    triplets.append((bill_text, positive, hard_negatives))
```

**输出**: ~4万个三元组 (每个 OSS 记录至少 1 个正样本 + 3 个硬负样本)

### 4.2 步骤2A: 微调向量模型

**模型**: BAAI/bge-large-zh-v1.5 → BGE-Construction

**方法**: SentenceTransformers + MultipleNegativesRankingLoss

```python
from sentence_transformers import SentenceTransformer, losses, InputExample

model = SentenceTransformer('BAAI/bge-large-zh-v1.5')

train_examples = []
for bill, pos_quota, neg_quotas in triplets:
    # 正样本对
    train_examples.append(InputExample(texts=[bill, pos_quota]))
    # 负样本对 (硬负样本)
    for neg in neg_quotas:
        train_examples.append(InputExample(texts=[bill, neg]))

train_loss = losses.MultipleNegativesRankingLoss(model)
model.fit(train_examples, loss=train_loss, epochs=3, warmup_steps=100)
model.save('models/bge-construction-v1')
```

**效果**: 
- 向量搜索时，"离心式泵" 的 top10 候选更可能包含正确的泵类定额
- 召回命中率提升 (当前 24 个召回失败预期减少 10-15 个)

**速度**: 
- 训练: ~2小时 (GPU, 4万样本 × 3 epochs)
- 推理: 完全不变 (同一个 BGE 架构, 同样 1024 维)

### 4.3 步骤2B: 微调重排序模型

**模型**: BAAI/bge-reranker-v2-m3 → BGE-Reranker-Construction

**方法**: CrossEncoder + BinaryCrossEntropyLoss

```python
from sentence_transformers import CrossEncoder

model = CrossEncoder('BAAI/bge-reranker-v2-m3')

train_samples = []
for bill, pos, negs in triplets:
    train_samples.append([bill, pos, 1.0])      # 正样本 label=1
    for neg in negs:
        train_samples.append([bill, neg, 0.0])  # 负样本 label=0

model.fit(train_samples, epochs=2, warmup_steps=50)
model.save('models/bge-reranker-construction-v1')
```

**效果**:
- 重排序时，正确定额得分更高，错误候选得分更低
- 16 个门控拒绝预期减少 8-12 个 (因为 top1 分数差距变大, gate 不再判定为 ambiguous)

**速度**: 
- 训练: ~1小时
- 推理: 完全不变 (同一个 CrossEncoder 架构)

### 4.4 步骤3: 自动测评部署

```bash
# 测评脚本 (已存在, 只需封装)
python eval/run_regression.py --pipeline-version "bge-construction-v1"

# 自动判断 (新增, ~30行)

"
```

## 6. 与 LightGBM LTR 方案的对比

| | LightGBM LTR | 自进化训练环 |
|---|---|---|
| 修什么 | 排序 (0个当前失败) | 召回 + 重排序 (40个当前失败) |
| 通用性 | 手工特征, 新省份需重训 | 语义学习, 跨省泛化 |
| 可持续 | 一次性训完就固定 | 加数据→重训→自动变好 |
| 前沿性 | 2017年技术 | 2023年 SentenceTransformers 微调 |
| 基础设施 | 需要写 LightGBM 训练代码 | 项目已有 SentenceTransformers |
| 代码量 | ~200行新代码 | ~150行新代码 |
