## 2. 修复一：修 gate — small_score_gap 不拒

### 2.1 根因

`ambiguity_gate.py:274-293`:

```python
gap = top1_rerank_score - top2_rerank_score
if gap < 0.03:     # agent_fastpath_score_gap 默认阈值
    return is_ambiguous=True, reason="small_score_gap"
    → 下游 _build_search_result_from_candidates 看到 is_ambiguous
    → best 可能变 None → 输出空结果
```

问题：用通用 CrossEncoder 的 rerank_score 差值来判断"是否可靠"。在建筑领域，通用模型对两个相近定额的打分可能只差 0.001，但它俩其实很好区分（比如 DN50 vs DN65）。

### 2.2 修复

在 `ambiguity_gate.py` 的 `small_score_gap` 分支加一道检查：如果 top1 候选有"强证据"（经验库命中 / 参数精确匹配 / 高 family_gate_score），则降级输出而非拒绝。

```python
# 当前:
if gap < policy.agent_fastpath_score_gap:
    return AmbiguityDecision(is_ambiguous=True, reason="small_score_gap", ...)

# 修复后:
if gap < policy.agent_fastpath_score_gap:
    # 检查是否有强证据支撑 top1
    has_strong_evidence = (
        top.get("param_match", True)
        and top.get("param_score", 0) >= 0.7
        and not top.get("family_gate_hard_conflict")
        and not top.get("feature_alignment_hard_conflict")
    )
    if has_strong_evidence:
        return AmbiguityDecision(
            can_fastpath=True,       # ← 改为 True
            is_ambiguous=False,      # ← 改为 False
            reason="small_gap_but_strong_evidence",
            ...
        )
    return AmbiguityDecision(is_ambiguous=True, reason="small_score_gap", ...)
```

### 2.3 改动量

`src/ambiguity_gate.py`: ~15 行

### 2.4 预期效果

9 个正解排第 1 但被拒的案例 → 修复 6-8 个
Top1: 60% → 66-68%

## 3. 修复二：微调向量模型

### 3.1 根因

当前 BGE 通用模型对建筑术语的语义理解不够：
- "离心式泵" 和 "泵类设备安装" 向量距离远
- "塑料管 DN50" 和 "室外PE塑料给水管 De50" 向量距离远

### 3.2 修复

用 OSS 中 45,784 条 (清单, 定额名) 配对微调 BGE：

```python
# tools/finetune_embedding.py
from sentence_transformers import SentenceTransformer, InputExample, losses

model = SentenceTransformer('BAAI/bge-large-zh-v1.5')

examples = []
for record in oss_records:
    # 正样本: 清单→正确定额
    examples.append(InputExample(texts=[record.bill_text, record.quota_name]))
    # 硬负样本: 清单→搜索到的相似但不同的定额
    for hard_neg in get_hard_negatives(record):
        examples.append(InputExample(texts=[record.bill_text, hard_neg]))

loss = losses.MultipleNegativesRankingLoss(model)
model.fit(train_objectives=[(train_dataloader, loss)], epochs=3)
model.save('models/bge-construction-v1')
```

### 3.3 改动量

`tools/finetune_embedding.py`: ~120 行（新建）
`config.py`: 2 行（模型路径）

### 3.4 预期效果

24 个召回失败 → 修复 12-16 个
Top1: 66-68% → 74-78%

### 3.5 速度

训练: ~2 小时 (GPU, 4.5 万 × 3 epochs)
推理速度: 不变（同架构，同维度）
索引重建: 安徽 chroma 需重建 (~90 秒)

## 4. 修复三：微调重排序模型

### 4.1 根因

当前 CrossEncoder (bge-reranker-v2-m3) 是通用模型。对于两个相近的建筑定额（如"镀锌钢管 DN50 螺纹连接"vs"镀锌钢管 DN65 螺纹连接"），通用模型给的分差很小，导致 gate 判为 ambiguous。

### 4.2 修复

用 OSS 配对微调 CrossEncoder：

```python
# tools/finetune_reranker.py
from sentence_transformers import CrossEncoder

model = CrossEncoder('BAAI/bge-reranker-v2-m3')

samples = []
for record in oss_records:
    samples.append([record.bill_text, record.quota_name, 1.0])      # 正样本
    for neg in get_hard_negatives(record):
        samples.append([record.bill_text, neg, 0.0])                 # 负样本

model.fit(samples, epochs=2)
model.save('models/bge-reranker-construction-v1')
```

### 4.3 改动量

`tools/finetune_reranker.py`: ~80 行（新建）
`src/reranker.py`: 5 行（加载微调后模型）

### 4.4 预期效果

7 个排序失败 → 修复 4-6 个
Top1: 74-78% → 78-82%
同时 gate 的 score_gap 变大 → 少触发 small_score_gap

### 4.5 速度

训练: ~1 小时 (GPU)
推理速度: 不变（同架构）
